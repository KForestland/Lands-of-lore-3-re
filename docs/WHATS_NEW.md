- **Machine word.** `LOL3.DAT` at file +0xCC is `4C 01`, the COFF machine word `0x014C`. `lol3_pht.py --check` re-reads those two bytes ([light maps](lol3-lmf-reader.md)).
- **Progression.** The 18 MAP scripts hold 131 portal commands, 82 of them with a predicate over a shared slot or the bound object's byte at +0x31. The event walkers take the first row that matches, so 49 rows also need every earlier row's guard to fail; 46 rows have neither a guard nor an earlier row (gate upstream, UNCONFIRMED). The page adds the level-to-level graph: all 18 levels are reached from QWOD0 along portal edges, 14 along guarded edges only. `lol3_progression.py --check` requires [progression](PROGRESSION.md) to equal the tool output.
- **Optional-header magic.** `LOL3.DAT` at file +0xE0 is `0B 01`, the PE32 magic `0x010B`. `lol3_pht.py --check` re-reads those two bytes ([light maps](lol3-lmf-reader.md)).
- **Cross-series check.** The shared format pages already stated the same archive, movie, music and cache figures as the current notes, and the name-hash note now states the shift of 6 ([engine](engine-evolution.md)). The shared glossary words are the same text in each game ([glossary](GLOSSARY.md)).
- **Settling tests.** Two open statements now name the test that would settle them: the sound name the `HWHIT` record requests in play, and a read watch on the four light-map header words ([dialogue](lol3-dialogue-dispatch.md), [light maps](formats/lmf.md)).
- **Close-out.** Ten open questions (Q1, Q3, Q4, Q5, Q7, Q8, Q10, Q11, Q12, Q13) each end with what was measured, what was tried, and what would settle the rest. States stay as they are. The five unread files stay unread ([open questions](OPEN_QUESTIONS.md)).
- **Program timestamp field.** The COFF TimeDateStamp at `LOL3.DAT` file +0xD0 is `0x37332C6E`, which encodes 1999-05-07 18:09:50 UTC ([light maps](lol3-lmf-reader.md)).
- **Shipped cache rows and light-map samples (Q1 partly, Q3 mostly).** The shipped 64,000-byte block holds 209 distinct values, and its bytes fit 100 rows of 640: 6,344 of 63,360 byte pairs 640 apart are equal, more than at any other distance from 1 to 2,000. The fill loop copies 0xFA00 bytes in one run and reads no pitch, so the width is inferred from the bytes ([cache](lol3-wsx-reader.md)). The four light-map words are colours from their own grids. Of 610,325, the nearest match to the assigned corner is the corner texel for 108,537, one texel away for 232,181, two to seven away for 139,039 and eight or more away for 130,568, so that neighbourhood is not the sampling rule ([light maps](lol3-lmf-reader.md)). The four photo files still show no short repeat in the first 65,536 bytes ([PHT](formats/pht.md)). `CYGNUS.PHT`, `RAIDER.PHT`, `quann.pht`, `yupa.pht` and the shipped `cdcache.wsx` stay unread.
- **Spell frames.** All 447 original spell frames store zero in word +8, so the effect reader stays on the one auxiliary row ([spell dispatch](lol3-spell-dispatch.md)).
- **Second spell counter on an edited save (Q12, partly answered).** One run loaded a copy of a game-written save with two items and two cast keys added by hand. Mana Cluster added a second-counter charge, and spell `0x57` then spent it, with no ordinary mana spending recorded for that cast; Ancient's Stone and spell `0x59` did the same for the first counter. [Edited saves](EDITED_SAVES.md) lists what the run showed and what a game-written save would still add; the editing rules are on the [save page](lol3-native-saves.md#editing-a-copy-of-an-original-slot). Open: taking the item in ordinary play, the exact counter on the HUD, each handler's effect and the on-screen names.
- **Rating.** The running-game line now also says how many answered probes rest on edited saves only; today none do ([how we rate](HOW_WE_RATE.md)).
- **Floor pickup (Q13, mostly answered).** In the original game, an item put on the ground and picked up again changed the predicted save fields, compared between game-written saves before and after. Open: the meaning of the remaining save fields ([native saves](lol3-native-saves.md#controlled-floor-pickup-in-bupp1)).
- **Texture upload on level 5 (Q6, answered for supported cache records and one device).** All 128 measured output words of one indexed texture row match lookups in the live colour table before upload. Open: the final screen composition and the separate SMD paths ([texture bake](lol3-texture-bake.md#live-level-5-indexed-row-and-upload)).
- **Mana Cluster on the lower floor (Q12, partly answered).** A run with the item's placement live could not reach its height, so that route stays blocked ([spell dispatch](lol3-spell-dispatch.md#dlow1-approach-with-the-native-placement-live)).
- **Cookbook.** The [cookbook](COOKBOOK.md) gives short recipes on your own game files, each with its command and the first lines it prints.
- **Tools at a glance.** The README lists what you can look at with your own game files, one line and one command each ([tools at a glance](../README.md#tools-at-a-glance)).
- **Shipped cache block (Q1, partly answered).** The 64,000-byte block is absent from every program and DLL in the install folder. The initializer's fill loop (`0x4E4E61–0x4E4E95`) writes it in 64,000-byte passes from locked screen memory, so it is a screen picture, not a stored resource; byte +0x17 keeps that fill. Which screen the shipped copy holds, and why it has 51 blocks, stay open ([native WSX reader](lol3-wsx-reader.md)).
- **PHT files.** They stay unread. The two programs do not store the four names in ASCII or UTF-16, the cycle length is not an immediate in the code, and the stored file-search patterns are the save-game wildcard `$*.*`, the `.\SAVEGAME` folder and a drive-root `*` for the free-space check. What the bytes are for stays open ([PHT](formats/pht.md)).
- **Glossary.** The [glossary](GLOSSARY.md) gives a one-line meaning to each term on the front page, the start page and the cookbook. A word shared with the other two games has the same meaning there. The rating still counts the glossary as a page, but not its label words.
- **Level sheets.** Each sheet lists the commands per opcode, the waypoint and path counts, and the five placement tables by type with their row ids. `lol3_level_report.py --check` fails when `docs/levels` differs from what the tool writes. `check_all.py` still runs twenty-four checks.
- **Reader listings.** The checks that already run can also print directory rows, format fields and the named table bytes. Nothing is written unless an output path is given, and `check_all.py` still runs twenty-four checks. The region byte-index table length is still a gap ([tools](../tools/README.md#reader-parity)).
- **Script browser.** `lol3_script_browser.py` groups one level's commands by opcode and prints the one-line meaning from the opcode page. It does not list each command.
- **Save inspector.** `lol3_save_header.py` prints the named slot fields, both directories and the other header bytes as hex with offsets. A level block long enough for a header lists its 75 section starts and lengths. `--check` uses a synthetic slot and the version compares in `LOL3.DAT`.
- **Level schematic.** The QWOD0 drawing adds hollow waypoint squares, path runs and the rows of all five placement tables (type 3, type 16, creature, mover, item), numbered from 1, with a legend. The scale fits the surface edges; marks outside them and overlapping numbers are left out and counted in the footer, and `--no-labels` draws no numbers. `--check` still regenerates that picture and compares it byte for byte.
- **Reader parity.** [tools/README](../tools/README.md#reader-parity) lists every current format and rules table with its reader, its check, and the text or drawing a reader gets. Rows with no such output are marked gap.
- **Link check.** `doc_links.py` resolves every relative link and anchor in the README and the docs, and `check_all.py` runs it.
- **Repeated blocks shown.** `lol3_pht.py` shows the four `.PHT` files are prefixes of one repeating cycle, and `lol3_cache_seed.py` shows the shipped cache body is one block repeated; these five files are listed separately in the rating, not counted as read. What the bytes mean and what reads them stays open ([PHT](formats/pht.md); Q1 is partly answered).
- **Counted rating.** The README and [STATUS](STATUS.md) show four counted lines instead of a percentage; [how we rate](HOW_WE_RATE.md) explains them.
- **Script commands (Q11, now mostly answered).** Each object command is traced for every kind of object it can target; floors and ceilings that move under script control are described ([opcodes](lol3-script-opcodes.md)).
- **Light maps (Q3, now mostly answered).** One flag marks smooth per-vertex lighting, and a colour field is identified ([LMF reader](lol3-lmf-reader.md)).
- **Spells and items (Q12, partly answered).** The two spell-cost discounts, the creature damage resistances, the second spell-charge counter and fourteen item-use handlers are traced ([spells](lol3-spell-dispatch.md), [items](lol3-item-dispatch.md), [combat](lol3-combat-dispatch.md)). Open: the second counter's live debit (later seen on an edited save, see **Second spell counter** above), each handler's effect and the on-screen names.
- **Level data (Q4, Q5 now mostly answered).** The remaining map spans and the level-object name table are tabulated; no reader of the labels or names is found. Two old claims about byte patterns in the shared MAP block were tested and found not to hold. Q8 stays partly answered: no reader of that block is known.
- **Shipped cache file (Q1, partly answered).** It is 51 copies of one block. The program, the game-written cache and the other data files are ruled out as its source; the real source is still unknown.
- **Music names (Q10, mostly answered).** Every stored string was hashed against the one unnamed music track. None matches, so the track stays unnamed.
- **Pictures.** Three misleading diagrams were removed; the one map drawing is regenerated and compared by its check.
