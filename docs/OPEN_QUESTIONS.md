# Open questions

Numbered so pages and the [STATUS table](STATUS.md) can point to them. Each says what is known and what would settle it.

For debugger procedures that use the original game, see [Needs a running game](NEEDS_A_RUNNING_GAME.md).

## At a glance

One line per question: its state and what would settle what is left. Device colour output (Q6, Q9) and some trigger conditions (Q12) need a running original game; the other next steps need only the original files.

| # | State | What would settle the rest |
|---|---|---|

| Q5 | Mostly | The 630 section-0 slots are names the loader skips, and a zero AI lookup leaves a zeroed buffer. A reader of those names remains open |

Final screen composition and the separate SMD paths remain open. |
| Q7 | Mostly | The editor-name branch (`0x43FFE4–0x44000D`) converges on the retail reader; only a differently framed standalone file remains unwitnessed |
| Q8 | Partly | The identical +0x244–+0x2F2C block in all 18 MAPs fits a leading u32 of 2,873 followed by 2,873 four-byte rows. The standard, conversion and editor cases use the same seeks. Find a reader that consumes rows at header +0xCC |
| Q9 | Answered for one renderer | Under Wine on a 16-bit display, the original intro converted RGB555 words to its RGB565 output (the format follows the display mode). Full-frame host comparison and other renderers remain open. |

That block is not in the executable, the other programs and DLLs in the install folder, or the game-written cache, and the shipped bytes at +0x76 are not allocator rows.
