# Open questions

Numbered so pages and the [STATUS table](STATUS.md) can point to them. Each says what is known and what would settle it.

For debugger procedures that use the original game, see [Needs a running game](NEEDS_A_RUNNING_GAME.md).

## At a glance

One line per question: its state and what would settle what is left. Device colour output (Q6, Q9), save pairs (Q13) and some trigger conditions (Q12) need a running original game; the other next steps need only the original files.

That block is not in the executable or in the game-written cache, and the shipped bytes at +0x76 are not allocator rows. | Q3 | LMF light maps. **Mostly answered:** native directory, grouped LZO1X and decoded member sizes confirmed; samples begin at +0x2C; disk bit 0 selects four per-vertex unit normals at +0x14–+0x2B (otherwise one repeated face vector); +8 is an RGB colour averaged into the surface light. Open: the four s16 at +0x0C–+0x13 | [Native LMF reader](lol3-lmf-reader.md) |
| Q4 | **Mostly answered.** Waypoints, paths and surfaces are read natively. Section-1's eight bytes each have a reader or a writer. Open: a reader of byte +6, of either label span, and of field 2 + 56×field 21 | [Native MAP reader](lol3-map-odf-readers.md) |

| Q8 | **Partly answered (the old claim is refuted, the labels are not explained).** MAP and ODF entries are joined, and the named bytes are placed: `C5 A5` is 195/2/1/0 in the QWOD0 texture, MAP, light map and ODF. | Q11 | Scripts. **Mostly answered:** all original MAP scripts frame exactly with the 39 native opcode lengths; the dispatch tables, event pools, predicates, timers and the 480 Hz host frame clock are mapped ([events](lol3-script-events.md)).
